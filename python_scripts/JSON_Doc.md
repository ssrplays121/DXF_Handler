# DXF to JSON Conversion Documentation

## Overview

This documentation describes the comprehensive JSON structure generated by the `convert.py` script when converting DXF files to JSON format. The converter extracts all available information from DXF files with robust error handling and detailed metadata tracking.

## JSON Structure

The generated JSON file follows a hierarchical structure with the following top-level sections:

```json
{
  "extraction_metadata": {...},
  "file_info": {...},
  "header": {...},
  "layers": [...],
  "linetypes": [...],
  "text_styles": [...],
  "blocks": [...],
  "modelspace": {...},
  "paperspace_layouts": [...],
  "errors_and_warnings": {...}
}
```

### 1. `extraction_metadata`

Contains metadata about the extraction process:

- `source_file`: Path to the original DXF file
- `success`: Boolean indicating if extraction completed successfully
- `processing_time`: Execution time (currently not implemented)
- `error_summary`: Summary of errors and warnings encountered

  - `total_errors`: Number of critical errors
  - `total_warnings`: Number of warnings
  - `missing_values_count`: Count of missing attributes
- `error_details`: Detailed error tracking information
  - `error_count`: Total number of errors
  - `warning_count`: Total number of warnings
  - `missing_values_summary`: Dictionary of missing attributes by context
  - `has_errors`: Boolean flag indicating if any errors occurred

### 2. `file_info`

Basic information about the DXF file:

- `path`: File path
- `version`: DXF version (e.g., "AC1027")
- `acad_version`: AutoCAD release version
- `encoding`: Character encoding used in the file

### 3. `header`

Contains all DXF header variables. Header variables store global drawing settings such as:

- `$ACADVER`: AutoCAD version
- `$EXTMIN`, `$EXTMAX`: Drawing extents
- `$LUNITS`, `$LUPREC`: Linear units and precision
- `$ANGDIR`, `$ANGBASE`: Angular settings
- `$CLAYER`: Current layer
- `$CECOLOR`: Current color
- And many other system variables

### 4. `layers`

Array of layer definitions with the following attributes for each layer:

- `name`: Layer name
- `color`: Color number (1-255)
- `linetype`: Linetype name (e.g., "CONTINUOUS")
- `flags`: Layer flags (0 = normal, 1 = frozen, etc.)

### 5. `linetypes`

Array of linetype definitions:

- `name`: Linetype name
- `description`: Human-readable description
- `pattern`: Pattern definition as string representation
- `error`: Present only if extraction failed for this linetype

### 6. `text_styles`

Array of text style definitions:

- `name`: Style name
- `font`: Font file name
- `height`: Default text height
- `width`: Width factor (1.0 = normal)
- `error`: Present only if extraction failed

### 7. `blocks`

Array of block definitions (symbol tables):

- `name`: Block name
- `base_point`: Insertion base point coordinates
- `entities`: Array of entities within the block
- `error`: Present only if extraction failed for this block

### 8. `modelspace`

Contains all entities in the model space:

- `name`: Always "Model"
- `entities`: Array of entity objects (detailed structure below)

### 9. `paperspace_layouts`

Array of layout (paperspace) definitions:

- `name`: Layout name (excluding "Model")
- `entities`: Array of entities in this layout
- `error`: Present only if extraction failed for this layout

### 10. `errors_and_warnings`

Comprehensive error tracking:

- `errors`: Dictionary of errors organized by context
- `missing_values`: Dictionary of missing attributes with occurrence counts

## Entity Structure

Each entity in the JSON follows a consistent structure regardless of type:

```json
{
  "type": "ENTITY_TYPE",
  "handle": "unique_handle",
  "layer": "layer_name",
  "attributes": {
    /* All DXF attributes from the dxf namespace */
  },
  /* Optional specialized fields depending on entity type */
}
```

### Common Entity Attributes

All DXF entities have access to graphical attributes that are available through the `dxf` namespace:

- `layer`: Layer name
- `color`: Color number
- `linetype`: Linetype name
- `lineweight`: Line weight value
- `true_color`: True color value (RGB)
- `transparency`: Transparency setting
- `ltscale`: Linetype scale
- `invisible`: Visibility flag

### Specialized Entity Fields

#### Text Entities (`TEXT`, `MTEXT`, `ATTRIB`)

- `text_content`: The actual text content stored in the entity

#### Block References (`INSERT`)

- `block_attributes`: Array of attribute definitions within the block
  - `tag`: Attribute tag name
  - `text`: Attribute value
  - `position`: Insertion coordinates

#### Geometric Entities

Geometric entities have a `geometry` field containing type-specific data:

##### `LINE`

- `start`: Start point coordinates
- `end`: End point coordinates

##### `CIRCLE`

- `center`: Center point coordinates
- `radius`: Circle radius

##### `ARC`

- `center`: Center point coordinates
- `radius`: Arc radius
- `start_angle`: Starting angle in degrees
- `end_angle`: Ending angle in degrees

##### `ELLIPSE`

- `center`: Center point coordinates
- `major_axis`: Major axis endpoint
- `ratio`: Minor/major axis ratio
- `start_param`: Start parameter (0 to 2π)
- `end_param`: End parameter (0 to 2π)

##### `LWPOLYLINE` (Lightweight Polyline)

- `vertices`: Array of vertex objects
  - `x`, `y`: Coordinates
  - `start_width`: Starting width at vertex
  - `end_width`: Ending width at vertex
  - `bulge`: Bulge factor (curvature)
- `closed`: Boolean indicating if polyline is closed

##### `POLYLINE` (Full Polyline/3D Polyline)

- `vertices`: Array of 3D vertex objects
  - `x`, `y`, `z`: 3D coordinates
- `closed`: Boolean indicating if polyline is closed

##### `POINT`

- `location`: Point coordinates

##### `SPLINE`

- `degree`: Spline degree
- `knots`: Knot values array
- `control_points`: Control points array
- `fit_points`: Fit points array

## Error Handling and Missing Values

The converter includes robust error handling that affects the JSON structure:

### Missing Attributes

When an expected DXF attribute is missing:

- The attribute is set to `None` in the output
- A warning is recorded in `errors_and_warnings.missing_values`
- The warning includes context and attribute name
- Only the first occurrence of each missing attribute type is printed to console

### Entity Errors

When an entity fails to process:

- A minimal entity object is created with:
  - `type`: Entity type (or "UNKNOWN")
  - `error`: Error message
  - `traceback`: Limited traceback information
  - `handle`: `null`
  - `layer`: "0" (default layer)
  - `attributes`: Empty object
  - `geometry`: `null`

### Critical Errors

If the entire extraction fails:

- The JSON contains only error information
- Includes detailed traceback and error description
- Contains file path and error summary

## Coordinate Systems and Data Types

### Vector Types

The converter handles modern ezdxf math types:

- `Vec3`, `Vec2`: 3D and 2D vectors
- `UCS`: User Coordinate System
- `Matrix44`: 4x4 transformation matrix
- These are serialized as string representations for JSON compatibility

### Units and Angles

- All measurements are in drawing units
- Angles are in degrees (except spline parameters which are in radians)
- Coordinates are in the current UCS (User Coordinate System)

## Usage Notes

### File Compatibility

- Supports DXF versions from R12 to latest
- Includes recovery mode for corrupted files
- Handles both binary and ASCII DXF formats

### Performance Considerations

- Large files may produce very large JSON outputs
- Complex entities (splines, polylines) have detailed geometry data
- Error tracking adds overhead but provides valuable debugging information

### Error Recovery

The converter attempts automatic recovery when:

- File structure errors are detected
- Entity data is corrupted
- Missing required attributes are encountered

### Recommended Post-Processing

- Filter entities by type or layer for specific use cases
- Process geometry data according to entity type
- Check `extraction_metadata.error_details.has_errors` before relying on data integrity
- Review missing values summary for data completeness assessment
